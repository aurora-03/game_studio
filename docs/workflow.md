# 素材工作流与 @ 引用

GameStudio 将游戏制作输入分为玩法需求、人物、场景、道具与音频节点，并保留笔记、普通素材与游戏结果节点。文字设计与文件素材属于同一个节点：人物可描述外观、性格和能力并绑定角色图片；场景可描述环境、关卡布局和镜头并绑定背景；道具可描述用途、交互和规则；音频可描述情绪、触发点和混音要求并绑定音频文件。

新项目建立包含玩法需求、四类素材与游戏结果的工作流。原有项目不会被批量替换，仍可继续编辑，也可在添加节点菜单中追加游戏制作工作流。新增工作流不覆盖已有节点、文件或版本。

一个项目可包含多个游戏结果。导演在存在多个结果时提供“生成目标”选择；插入新工作流会选中其新游戏节点。每个结果保留自己的版本，迭代使用选中节点的源版本；尚无版本的新节点须先生成，不会自动借用另一个游戏的激活版本。生成目标也会随项目设置保存。

## 编辑与引用

在节点描述和导演输入框中键入 `@`，搜索并选择当前项目中的画布节点。引用显示节点名称，绑定实际节点 ID；重名不会让后台猜测引用对象。选择材料后，生成读取其角色、当前设计、规格、绑定文件和进一步引用的材料。

引用保存为 `{ nodeId, label, start, end }`：`label` 为插入时的显示名称，`start`/`end` 为文本中 `@名称` 的 UTF-16 范围。节点后来改名，已有引用仍然指向相同 ID。插入、删除或移动文本时，编辑器更新引用范围；手动输入一个名字不会自动变成已绑定引用。已经选择但被删去的节点须重新选择或移除引用后才可生成。

数据格式还支持 `data.referenceNodeIds` 依赖列表。画布连线、该列表和内联 `@` 使用相同的生成上下文收集规则；界面主要通过连线和内联引用编辑节点关系。

## 生成上下文

一次任务会收集目标游戏节点的上游连线、明确选择的节点和文件，以及请求文本的 `@` 引用；再递归收集这些节点的依赖、上游连线与 `@` 引用。循环依赖按 ID 去重，避免无限遍历。同一个材料被多个节点引用时只进入上下文一次。

上下文保留节点类型、设计文字、规格和文件归属。图片以本机文件路径传给 Codex 的 `--image` 参数，并在文字上下文中标明对应素材 ID、URL 和图片顺序；TXT/JSON 文档提供有界的实际文本，音频提供可供游戏使用的真实文件 URL 与设计要求。音频不会作为视觉附件发送。

模型固定为本机 Codex CLI 的 `gpt-6.1-sol`。它输出完整 HTML5 游戏；角色、背景和音效节点本身不调用单独的图片或声音生成服务。

任务提交时冻结生成上下文。排队后修改人物描述、名称或参数不会改变已提交任务，下一次提交才会使用新设计。正在排队或运行的项目会阻止删除文件，确保已提交的图片路径仍可读。后台不会通过忽略坏引用或截断图片数量来伪装完成：引用不存在、属于其他项目、范围错误或超过引用限制时会明确拒绝。

每次工作流最多引用 20 个文件，其中最多 8 张视觉参考图。Codex 图片附件支持 PNG、JPG、WebP 和 GIF；已上传的 AVIF 在引用生成时会要求先转换为支持的格式。文件可被多个节点共用，按文件 ID 去重；模型看到的图片序号与实际 CLI 附件顺序保持一致。

## 文件与复制

每个节点可绑定多个文件，存为 `data.assetIds`；旧项目的单文件 `data.assetId` 仍受支持。素材面板可搜索文件、按图片/音频/文档筛选，将文件作为指定类型的新节点，或绑定到选中的已有节点。

删除一个未被历史游戏引用的文件会解除人物、场景、道具和音频节点的文件绑定，保留设计文字与节点。游戏历史源码仍使用的文件受保护，删除返回明确冲突，避免已保存版本失效。普通旧式文件节点随其文件删除；指向不存在节点的引用不能继续悄悄生成。

复制项目时，文件取得新的项目内 ID 与 URL，绑定列表、描述和规格中的素材 URL 及游戏源码更新为副本文件。节点 ID 在独立项目内保留，因而节点引用与依赖可以原样保留；副本后续编辑不影响原项目。重启后设计字段、引用范围、文件绑定、节点图和版本由本机数据恢复。

## 验证边界

`tests/e2e/workflow.test.js` 使用真实 HTTP 服务与受控子进程，捕获后台实际发送给 CLI 的参数和提示词，检验素材角色、文件字节、图片顺序、引用身份、循环处理、失效引用、复制、排队快照与重启。受控进程只验证传输和存储，不代表真实模型生成证据。界面和真实 Codex 检查的结果单独记录于 [验证记录](verification.md)。
