# 架构与生成边界

GameStudio 是一个在本机运行的创作网站。浏览器通过本机 HTTP API 管理项目；Node 服务持久化项目状态、排队生成任务并调用已经登录的 Codex CLI。AI 产物是可运行的浏览器游戏，每次完成生成或源码编辑都会增加一个版本。

## 数据对象

| 对象 | 内容 | 用途 |
| --- | --- | --- |
| Project | 项目名称、描述、状态、画布、设置、消息、素材与版本 | 长期保存一次游戏制作过程 |
| Node / Edge / Viewport | 节点内容、引用关系、坐标与缩放 | 可视化编辑创作输入与产物 |
| Asset | 原文件、名称、MIME 类型、尺寸、项目内 URL | 将参考素材带入生成和后续修改 |
| Job | 提示词、模型、模式、来源版本、状态、日志、错误、结果版本 | 让耗时任务可观察、取消和追溯 |
| Version | HTML 源码、标题、说明、操作方式、来源与创建时间 | 预览、比较、继续修改与导出 |
| Template | 示例需求、类型与设置 | 为新项目建立可修改的开始点 |

人物、场景、道具和音频使用 `character`、`scene`、`prop`、`audio` 节点类型。`data.content` 是当前编辑的设计文字；明确空字符串表示用户清空，不能再回退至旧模板提示词。`data.specifications` 保留对应的结构化设计字段，`data.assetIds` 绑定多个真实文件，旧版 `assetId` 继续兼容。

`data.mentions` 与任务 `mentions` 记录文本的 `@` 引用及节点 ID、显示快照和 UTF-16 范围，`data.referenceNodeIds` 保存明确依赖。后台用同一遍历收集连线、节点依赖和内联引用，递归去重循环；创建任务之前检查引用范围和项目内文件/节点归属，失败不创建伪成功任务。详细行为见 [素材工作流](workflow.md)。

前端手动编辑和 AI 生成共同使用项目、节点与版本接口。SSE `/api/events` 发布状态变更；重新打开页面时从持久化状态恢复，而不是依赖仍然存在的前端组件。

## CLI 调用

CLI 由后端使用参数数组启动；模型固定为 `gpt-6.1-sol`。项目需求、相关节点、参考素材和迭代源版本组成上下文。任务运行在为该次任务准备的目录中。前端不直接执行 shell，不接收登录令牌，也不持有 API Key。

任务提交时保存私有的生成上下文快照，包含实际提示词与引用图片路径；公开任务 API 省略该快照，避免泄露本机路径。文字/JSON 文档内容与迭代源码在快照中冻结；任务排队或执行时禁止删除项目文件以维护图片路径。后续画布编辑影响下一次任务。

成功必须同时满足 CLI 正常完成和存在有效游戏产物。CLI 非零退出、超时、被取消或缺少产物会进入对应失败/取消终态。演示模板与测试夹具不替代真实生成。

## 隔离与本机访问

服务默认仅监听 `127.0.0.1`。修改类请求验证来源，防止外部网站对本地服务提交任务。预览在允许脚本、不给同源权限的 iframe 中运行，并以 CSP 限制对外连接。文件路径、上传和导出限定在项目数据目录中。

这是本机创作工具的部署方式。开放到公网需要额外实现身份认证、用户隔离、额度和队列配额；当前默认不会提供公共远程访问。

## 目录分工

| 目录 | 内容 |
| --- | --- |
| `src/` | React + TypeScript 界面、画布与 API 客户端 |
| `server/` | Express API、持久化、Codex 适配与队列 |
| `public/` | 网站图标与静态文件 |
| `data/` | 本机项目、上传、游戏版本、任务状态；不提交到 Git |
| `tests/backend/` | 数据和生成输入单元测试 |
| `tests/e2e/` | 使用受控 CLI 的真实 HTTP 集成测试 |
| `docs/` | 验收、运行和验证说明 |

具体 CLI 参数、环境变量和运行命令以已核实的 `README.md` 及 `server/` 实现为准。
